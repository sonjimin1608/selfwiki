**CANVAS 구조 개편**은 jms19가 2026년 9월 23일부터 28일까지 CANVAS 백엔드에서 진행한 Phase 0~8 개편이다.[^1] 기존 경로를 건드리지 않고 새 체계를 옆에 추가한 뒤 하나씩 옮기는 방식으로 했다.[^1] jms19는 [[Son Jimin]]의 회사 계정이다.[^2] 전체 맥락은 [[CANVAS 백엔드 개발]] 참고.

## 단계

- Phase 0: 기준선을 쟀다. 캔버스 JSON 1.7GB 중 거대 문자열이 75.9%, 캐시 저장소 563.6GB 중 중복 후보가 260.2GB였고, 라우트 180개 중 37개가 인증이 없었다.[^1] 절대경로로 남의 파일 접근, 업로드 청크 충돌, 유저 컨테이너의 docker.sock을 먼저 막을 위험으로 정했다.[^1]
- Phase 1: UUIDv7 기반 file_id 체계, 폴더·파일·속성·자산·업로드 세션 테이블, 객체 저장 레이아웃, FileService와 `/v2` 업로드·폴더·파일 API를 만들었다.[^1]
- Phase 2: 서명 URL(내용 버전 포함, immutable 캐시), 인가 계층(파일·폴더 단위 권한 확인), 프리뷰·deepzoom 백그라운드 생성을 넣었다.[^1]
- Phase 3: 노드 타입 레지스트리(파라미터 화이트리스트), 워크스페이스 그래프·Artifact·custom code 테이블, dtype을 보존하는 Artifact 입출력, 서명 계산, Artifact API를 만들었다.[^1]
- Phase 4: 노드 실행 기록·신선도·실행 계획(위상정렬), 새 그래프를 옛 엔진에 잇는 어댑터, 낙관적 동시성 op API·실행/취소·WebSocket을 만들었다.[^1]
- Phase 5: 상한 없는 캐시를 모두 LRU로 바꾸고, v2 실행을 비동기 job으로 돌리며 WebSocket으로 진행을 알리고, pickle 없는 입출력의 v2 custom code를 만들고, 유저 컨테이너 마운트를 줄였다(소스 읽기 전용, ~/.ssh 제거).[^1]
- Phase 6: 불변 스냅샷으로 파이프라인을 컴파일하고, 일괄 실행 러너와 파이프라인 → 워크스페이스 가져오기를 만들었다.[^1]
- Phase 7: 데이터허브 파일·폴더 공유, 워크스페이스 참여자 보기 권한, 참여자용 노드 파일 미리보기를 넣었다.[^1]
- Phase 8: 모니터링 지표(GPU 슬롯·WS 세션·job 큐·디스크), GC·보관 정책 스크립트, 최종 비교 리포트, 레거시 제거 체크리스트를 만들었다.[^1]

## 이전·호환

- 레거시 캔버스를 v2로 바꾸는 변환기를 만들어 저장된 그래프 426개·노드 3,415개를 통과시켰고, v2 복사·게시 열람·제자리 변환도 넣었다.[^1]
- 기존 클라우드 파일을 file_id로 옮기는 이전 도구(하드링크, dry-run)와 유저 컨테이너 재생성 도구를 만들었다.[^1]
- 레거시 라우터를 지웠다가 프런트가 아직 쓰고 있어 복원했다.[^1]
- 레거시 경로로 남의 파일을 읽을 수 있던 보안 문제를 고쳤다.[^1]
- Image Processing Resize가 원본 레벨을 통째로 읽던 문제를 고쳐 3.20초를 0.49초로 줄였다.[^1]
