**CANVAS 백엔드 개발**은 jms19가 2026년 9월부터 11월까지 VIENCE의 CANVAS 백엔드 저장소에 커밋한 작업을 정리한 문서다.[^1] 2026-08-01 ~ 11-18 기간 커밋 156개 중 jms19가 95개, 다른 팀원이 61개를 썼다.[^1] jms19는 [[Son Jimin]]의 회사 계정이다.[^2] 에이전트 작업은 [[CANVAS AI 에이전트]], 9월 말 개편은 [[CANVAS 구조 개편]] 참고.

## 데이터 저장소 이관 (2026-09-15)

- Alembic을 도입하고 기동 시 advisory lock으로 마이그레이션을 한 번만 돌게 했다.[^1]
- 파일 키·진행 pickle·이미지 정보, 모델 정보 JSON, 스케줄러 JSON을 각각 DB 테이블로 옮겼다(스케줄러는 행 잠금 트랜잭션).[^1]
- 노드 실행 결과·커스텀 코드 캐시 키를 하나로 통일하고, 이관·스모크 테스트·되돌리기 도구(dry-run 기본)를 만들었다.[^1]

## 뷰어·추론 재사용 (2026-09-16 ~ 09-21)

- 뷰어 타일을 PNG에서 JPEG로 바꾸고 ICC를 제거해 1,329KB를 11~20KB로 줄였고, 중간 줌 검은 타일 문제를 고쳤다.[^1]
- 타일 이음매, 오버레이 무손실 PNG, 마스크 8bit 매핑을 고쳤고, Crop 프리뷰가 원본 전체를 읽던 문제를 21.7초에서 0.73초로 줄였다.[^1]
- AI Connector 결과를 상류 체인이 재사용하지 못해 같은 추론을 두 번 돌던 문제를 고쳤다.[^1]
- 모델을 고르지 않은 AI Connector가 GPU 슬롯을 328.6초 기다린 뒤 실패하던 문제를 검증을 슬롯 전으로 옮겨 고쳤다.[^1]

## 구조 개편 (2026-09-23 ~ 09-28)

file_id 체계, 서명 URL·인가 계층, 그래프·Artifact, 비동기 실행 job, v2 custom code, 파이프라인, 공유, 모니터링, 레거시 변환을 Phase 0~8로 진행했다.[^1] 자세한 내용은 [[CANVAS 구조 개편]] 참고.

## 에이전트와 운영 안정화 (2026-10)

- 학습 코드 에이전트, 자동 모델 에이전트·저장소 검색, 에이전트 전반 개편을 했다.[^1] 자세한 내용은 [[CANVAS AI 에이전트]] 참고.
- 대형 WSI 처리 중 호스트 OOM을 막기 위해 노드 시작 전 메모리를 확인하고 유저 컨테이너 합계 cgroup과 사용자 코드 메모리 한도를 두었다.[^1]
- DeepZoom 타일을 NFS에 낱개로 굽느라 NFS가 몇 분씩 멈추던 문제를 로컬에서 zip으로 굽고 한 파일만 복사하는 방식으로 고쳤다.[^1]
- AI Connector 폴더를 데이터허브 DB에 하드링크로 등록하고, 데이터허브 삭제·이동을 디스크에 반영했다.[^1]
- 노드 단계 진행률, SVS 결과 메타데이터(MPP·배율), 학습 배율 맞춤 추론을 넣었다.[^1]
- Dataset Configuration이 끝난 추론을 다시 돌던 문제(45,904 타일, 6분)를 고쳤다.[^1]
- 노드 캐시 무효화, DZI 지연, NFS 저장 시 GIL 정지, 취소 후 GPU 캐시 정리 같은 운영 이상을 일괄 수정하고 백필·재서명 도구를 만들었다.[^1]

## 부하·보안·등급제 (2026-11 초)

- 이벤트 루프 위 동기 DB 호출로 생기던 커넥션 풀 고갈·교착을 고쳐, 시험에서 340건 중 3건 성공이던 것을 340건 모두 성공으로 바꿨다.[^1]
- 로그인 폭주 때 백그라운드 작업이 ssh 동안 DB 커넥션을 쥐던 문제를 고쳐, 시험에서 로그인 실패 244건이던 것을 375건 모두 성공으로 바꿨다.[^1]
- My Hub 목록 서버 정렬·필터·페이지네이션, 결과 이미지의 슬라이드 호환(.svs) 저장을 넣었다.[^1]
- 인증·세션·등급제를 개편했다: google id_token 서명 검증, bcrypt 전용, 가입 서버 재검증, 인증코드 DB(5회 실패 무효), opaque refresh 토큰(SHA-256 저장)과 HttpOnly 쿠키·rotation·재사용 감지, 플랜·구독·사용량 기반 기능 잠금과 한도, 관리자 API.[^1]

## 추론 성능과 GPU 칸 (2026-11 중순)

- HoVer-Net을 GPU forward와 CPU 후처리 파이프라인으로 나눠 타일 처리량을 초당 1.11장에서 3.05장으로, 4096² 슬라이드를 23.9초에서 11.9초로 줄였다(결과 픽셀 차이 0).[^1]
- 추론의 처음부터 끝까지를 GPU 상한 가까이 끌어올렸다: 확률 블렌딩·인스턴스 마스크 GPU 처리, 결과 처리 별도 스레드, level-0 JPEG 직접 디코드(57ms→12ms), 뷰어 마스크 GPU 색칠.[^1]
- 그 결과 모델 로드를 뺀 시간이 Tumor 384→76초, Mitosis 80→26초, Steatosis 241→38초, SAM3 Cell Seg 55→37초, TMA 29→18초, IHC 127→121초, HoVerNet 108→87초가 됐고 7종 모두 결과 픽셀 차이가 0이었다.[^1]
- 추론을 빈 GPU 칸부터 배정하는 대기열(FIFO, "GPU 대기 중: N번째" 표시)을 만들어 옛 추론 API는 38.3초에서 14.1초로, 스케줄러는 552초에서 89초로 줄었다.[^1]
